# 执行可靠性与人工接管

这些改进参考同源分叉仓库 `shangyuan006/codex-bookmark-checkin-template`
的 `4fc155937c447db1d00bae3b1a36829418b7fbe7`，按本项目的执行租约、账号绑定及
观测契约重新实现。原有 PT、OCR、Bitwarden 辅助验证、Harvest 补签和当日结果
保护保持原来的接口；没有引入第二份提交流水或假定已签到规则。

## 状态保存

执行层通用 `atomicWriteJson` 使用每次独立的临时文件。Windows 的
`EPERM`、`EACCES`、`EBUSY` 只对同一临时文件的替换进行有限退避重试，总等待
上限 1.55 秒；不会重新运行产生该结果的签到动作。永久写入失败保留旧文件。
其他文件系统错误不按文件占用重试。

## 点击保护

通用签到按钮沿用现有选择顺序，先绑定实际元素、检查可点击性及同源目的地，
再登记原有提交意图并点击。公告插入或 DOM 索引变化不能将点击移到另一个按钮。
点击开始后的异常继续作为未知提交处理。OpenCD 等已登记的纯弹窗入口沿用原有
豁免，实际验证码提交仍由成熟流程保护；访问即签到的 GET 入口仍先登记意图。

## OAuth 诊断

自动浏览器和原生 OAuth 恢复记录固定阶段：启动、目标登录、上游登录、授权、
回调、账号核对及结果核对。诊断只含阶段、随机流程号、站点哈希、耗时与有限布尔
标记，不记录页面正文、URL、账号、密码、验证码或存储内容。单次最多 64 条，
每日文件上限 1 MiB，专用诊断日志保留 14 天。

stderr 检查点可在助手超时后恢复最后阶段；检查点不能证明登录或签到成功。
最终身份和当日证据继续由既有接口验证。

## 人工登录前复核

面板登录请求进入执行电脑后，对已有被动读取能力的默认单账号 PT，使用现有
双层锁和只读网关再核验一次。已签到则结束请求；账号已登录但未签到则提示继续
原签到任务；维护状态单独说明。网络读取失败仍保留用户原先的人工登录能力，
范围或账号绑定变化则停止。此步骤不会补签，也不增加自动重试次数。

## 地址变更

独立迁移页和未授权来源跳转分别标记 `site_migration` 与
`bookmark_origin_changed`，停止后续候选、重试及普通登录接管，提示核对书签。
历史公告、浏览器错误页及已知 OAuth 登录路径不会单凭文字或来源被误当成迁移。
地址变更属于外部原因，从项目成功率分母排除；原始未知提交仍保留审计。

## 更新边界

发布和回滚除了取得执行锁，还检查实际人工接管状态，包括
`awaiting_manual_handoff`、`pending_verification` 及活动手动会话。
进行中的人工流程应先结束或复核。代码更新和回滚不覆盖私人配置、Profile、
签到记录及历史证据。
